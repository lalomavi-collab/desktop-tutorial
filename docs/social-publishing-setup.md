# פרסום ישיר ללינקדאין ולפייסבוק, בלי Zapier

המנגנון עובר לדבר מול ה-API של הפלטפורמות. מה שזה קונה: הודעת שגיאה שמצביעה על
הבעיה האמיתית (טוקן שפג, הרשאה חסרה, מזהה שגוי) במקום וובהוק שקיבל את הבקשה
באישור והשמיט אותה בשקט. מה שזה עולה: ארבעה סודות שצריך להפיק, ואחד מהם צריך
חידוש תקופתי.

הקוד: `scripts/publish_post.py`. הטקסטים: `posts/campaign_sept_2026.json`.
הכרטיסים: `lalum-app/public/og/`. הוורקפלואים: `.github/workflows/publish_0*_campaign.yml`.

---

## מה צריך להגדיר

ארבעה סודות ב-Settings → Secrets and variables → Actions:

| סוד | מה זה |
|---|---|
| `FACEBOOK_PAGE_ID` | המזהה המספרי של העמוד העסקי |
| `FACEBOOK_ACCESS_TOKEN` | טוקן של **העמוד**, לא של המשתמש |
| `LINKEDIN_ACCESS_TOKEN` | טוקן OAuth עם הרשאת פרסום |
| `LINKEDIN_AUTHOR_URN` | `urn:li:organization:<id>` לפרסום כדף החברה, או `urn:li:person:<id>` לפרסום כאדם |

פלטפורמה שהסודות שלה חסרים מדולגת ומדווחת, ולכן אפשר להתחיל עם פייסבוק לבד
ולהוסיף את לינקדאין כשהאישור מגיע.

---

## פייסבוק. זה החלק הקל

1. היכנס ל-developers.facebook.com, צור אפליקציה מסוג Business, וקשר אותה
   לחשבון העסקי שמנהל את העמוד.
2. פתח את **Graph API Explorer**, בחר את האפליקציה, ובחר את העמוד תחת
   User or Page.
3. סמן את ההרשאות: `pages_manage_posts`, `pages_read_engagement`,
   `pages_show_list`. הראשונה היא זו שמפרסמת, בלעדיה כל השאר לא עוזר.
4. לחץ Generate Access Token ואשר. מה שקיבלת הוא טוקן **משתמש**, קצר מועד.
5. החלף אותו לטוקן ארוך מועד:
   `GET /oauth/access_token?grant_type=fb_exchange_token&client_id=<APP_ID>&client_secret=<APP_SECRET>&fb_exchange_token=<הטוקן שקיבלת>`
6. עם הטוקן הארוך, קרא `GET /me/accounts`. בתשובה מופיע העמוד: השדה `id` הוא
   `FACEBOOK_PAGE_ID`, והשדה `access_token` שלו הוא `FACEBOOK_ACCESS_TOKEN`.

טוקן עמוד שנגזר מטוקן משתמש ארוך מועד אינו פג מעצמו. הוא כן נשבר אם תשנה סיסמה,
תסיר את האפליקציה, או תשנה הרשאות. אם הפרסום נכשל פתאום עם 190, זו הסיבה.

## לינקדאין. כאן נמצא הקושי, ולא בקוד

לינקדאין לא מאפשרת פרסום דרך API בלי לאשר את האפליקציה מראש. זה תהליך מול
לינקדאין, לא הגדרה, והוא יכול לקחת ימים. שווה להתחיל אותו עכשיו במקביל לכל השאר.

1. היכנס ל-linkedin.com/developers, צור אפליקציה, וקשר אותה לדף החברה של LALUM.
   האימות מחייב שתהיה מנהל של הדף.
2. בלשונית **Products** בקש את המוצר המתאים:
   * לפרסום **כדף החברה**: המוצר שמעניק `w_organization_social`. נכון לכתיבת
     המסמך הוא נקרא Community Management API, והוא **דורש אישור מלינקדאין**.
     שמות המוצרים אצלם משתנים מדי פעם, אז חפש את זה שמעניק את ההרשאה הזו.
   * לפרסום **כאדם פרטי**: המוצר שמעניק `w_member_social`. בדרך כלל זמין מיד
     בלי אישור. הפוסט יופיע מהפרופיל שלך ולא מדף החברה.
3. בלשונית Auth הפק טוקן בזרימת OAuth. הטוקן שמתקבל הוא `LINKEDIN_ACCESS_TOKEN`.
4. את ה-URN:
   * דף חברה: המזהה המספרי מופיע בכתובת של עמוד הניהול. הרכב
     `urn:li:organization:<המספר>`.
   * אדם: קרא `GET https://api.linkedin.com/v2/userinfo` עם הטוקן, וקח את השדה
     `sub`. הרכב `urn:li:person:<sub>`.

**מה שחייב להיאמר:** טוקן של לינקדאין פג אחרי כ-60 יום. אין דרך לחדש אותו
מעצמו בלי לממש זרימת refresh token, ולכן פעם בכחודשיים תצטרך להפיק טוקן חדש
ולעדכן את הסוד. זה המחיר של ויתור על מתווך. אם זה מטריד, אפשר לממש חידוש
אוטומטי, וזו עבודה נפרדת.

## איך בודקים בלי לפרסם

```
python3 scripts/publish_post.py 010 --dry-run
```

בונה את הכל, מדפיס לאן היה נשלח ומה, ולא שולח דבר. שימושי כדי לוודא שהסודות
נקראים ושהכרטיס הנכון נבחר, לפני שמוציאים פוסט אמיתי.

## איך מפרסמים

Actions → הוורקפלואו של הפוסט → Run workflow → Branch: main.

אין תזמון אוטומטי באף אחד מהם. `cron` יתווסף רק כשתאמר שהטיוטות נקראו ואושרו.

## מה קורה כשמשהו נכשל

הסקריפט מדפיס את קוד השגיאה ואת הודעת הפלטפורמה כלשונה, ומוסיף למה זה קורה
בדרך כלל. פלטפורמה אחת שנכשלת לא מונעת מהשנייה לפרסם. אם שתיהן נכשלו או דולגו,
ההרצה יוצאת עם כישלון, כי הרצה ירוקה שלא פרסמה כלום היא התוצאה הגרועה מכולן.

## מה שנשאר על Zapier

שבעה וורקפלואים ישנים (`publish_002` עד `publish_008`, `social-post.yml`
ואחרים) עדיין מפנים לסודות `ZAPIER_*`. אף אחד מהם לא רץ אי פעם, והם לא משפיעים
על שום דבר. אפשר למחוק אותם בבת אחת, תגיד ואמחק.
