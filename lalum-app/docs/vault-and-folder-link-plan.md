# כספת, פתיחת קבצים וקישור תיקיית LALUM: ממצאי בירור ותוכנית

סטטוס (14.10.2026): שלב 0 (בירור) הושלם. כיוון ג (פתיחת קובץ מקור) נכתב ונבדק ואינו פרוס ולא מוחל. כיווני א וב (תיקייה מקושרת, סנכרון שרת) לא התחילו.

## 1. מה נמצא בכספת היום

נתוני פרודקשן, נבדקו בקריאה בלבד:

- דלי פרטי `matter-originals`, 243 אובייקטים, כ-65MB. כל מסמך חי יש לו קובץ מקור.
- פורמטים: Word (104), PDF (92, כ-61MB מתוך 65), markdown (33), טקסט (14). הקובץ הגדול ביותר 8.6MB.
- מגבלת קובץ בדלי: 50MB. סוגים מותרים: PDF, docx, טקסט, markdown, HTML.
- מדיניות: הוספה וקריאה ומחיקה לאותו משרד, עם MFA. קריאה לתפקידי שותף, עורך דין ו-ADMIN.

**לא קיים בקוד:** שום מסך אינו קורא קובץ מקור. הכספת נכתבת ואינה נפתחת מהאפליקציה. זה עיקר הפער שכיוון ג סוגר.

## 2. ממצאי בירור (מקורות: תיעוד Supabase הרשמי)

1. **גיבויי מסד הנתונים אינם כוללים את קבצי האחסון.** הציטוט מהתיעוד: "Database backups do not include objects you store via the Storage API, as the database only includes metadata about these objects" (https://supabase.com/docs/guides/platform/backups). לכן לקבצי המקור בכספת אין היום עותק שני אוטומטי. מחיקה או תקלה באחסון אינן ניתנות לשחזור מגיבוי המסד. עד סגירת תיק (ארכיון ל-Drive לפי הסכמה) העותק האחר היחיד הוא הקובץ המקורי אצל המשרד.
2. **גיבוי המסד עצמו** תלוי בתוכנית: יומי ל-7 ימים ב-Pro, ושחזור לנקודת זמן כתוסף בתשלום. **לא ידוע לי איזו תוכנית פעילה בפרויקט.** צריך לבדוק בלוח הבקרה.
3. **אפשר לגבות את האחסון דרך נקודת S3 תואמת** (rclone, AWS CLI) או דרך סקריפט הורדה: https://supabase.com/docs/guides/storage/management/download-objects. זה הכלי לעותק שני.
4. **מגבלות:** בתוכנית חינמית 50MB לקובץ, ב-Pro עד 500GB (https://supabase.com/docs/guides/storage/uploads/file-limits). מגבלת הדלי היום 50MB, והיא הגדרה שלנו ולא מגבלת תוכנית: סריקה או הקלטה גדולה מ-50MB תידחה עד שמעלים את המגבלה.
5. **קישור חתום** (`createSignedUrl`) מתקבל בשניות ויכול לכלול שם הורדה (`download`): https://supabase.com/docs/reference/javascript/file-buckets-createsignedurl. זה בסיס כיוון ג.
6. **אזור הפרויקט: eu-central-1 (פרנקפורט).** חומר חסוי של לקוחות ישראלים נשמר באיחוד האירופי. צריך לבדוק מול הנחיות רשות הגנת הפרטיות והסכמי הלקוחות אם נדרשת הערה בהסכם שכר הטרחה.

**עדיין לא נבדק:** האם יש OCR לסריקות (מסמך סרוק נכנס כטקסט ריק?), עלות לפי נפח למשרד עם עשרות תיקים, סריקת נוזקות לפני קליטה.

## 3. כיוון ג: פתיחת קובץ מקור (נכתב, לא פרוס)

- **מסד (0047):** `lalum_open_original(doc)` מחזירה נתיב, סוג, גודל וקוד תיק רק אם: המסמך חי, התיק חי, המשתמש בתוך המשרד ובעל גישה לתיק, והוא רשאי לראות שמות לקוחות (שותף או עורך דין עם MFA). היא רושמת ביומן הביקורת `DOCUMENT_ORIGINAL_OPENED` עם גיבוב הקובץ בלבד, בלי שם ובלי נתיב. ניסיון מסורב לא נרשם ואינו חושף סיבה.
- **פונקציית Edge (`lalum-open-original`):** קוראת למסד בשם המשתמש (ה-JWT שלו), ורק אם קיבלה כן מחתימה קישור ל-60 שניות. שם ההורדה הוא קוד התיק ומזהה קצר, לעולם לא שם הקובץ המקורי.
- **ממשק:** כפתור "פתיחת המקור" בכרטיס מסמך, רק למי שרשאי, ורק כש-`VITE_OPEN_ORIGINAL=1`. כך מיזוג הקוד אינו מציג כפתור שלא עובד.
- **הפעלה (באישור המשרד):** החלת 0047, פריסת הפונקציה (עם `ALLOWED_ORIGINS` של האפליקציה), הגדרת `VITE_OPEN_ORIGINAL=1` בפריסת הממשק, ובדיקה של פתיחה אחת ושל מסורבת אחת.
- **מגבלה ידועה:** מדיניות הקריאה הישירה לדלי (`lalum_originals_read`) עדיין קיימת, ולכן שותף מתוחכם יכול לעקוף את הפונקציה ולחתום קישור בעצמו, בלי רישום. סגירתה היא שלב נפרד שחייב בדיקה על ענף Supabase: מחיקות באחסון עשויות להסתמך על מדיניות הקריאה, וחסימה שגויה עלולה לשבור מחיקה סופית וניקוי העלאה כושלת. עד אז הכיסוי ביומן מלא רק לפתיחות דרך האפליקציה.

## 4. הצעת המשך (לא בוצע)

1. **עותק שני לכספת של תיקים פעילים.** האפשרות המומלצת: סקריפט לילי בצד שרת, דרך נקודת ה-S3, לעותק מוצפן אצל המשרד (מפתח בידי המשרד). זו סטייה מההחלטה "Drive לתיקים סגורים בלבד", וצריכה הכרעה מפורשת: חומר חסוי של תיק פעיל יוצא מ-Supabase, ולכן רק מוצפן ולא ל-Drive קריא.
2. **סגירת הקריאה הישירה** אחרי בדיקה על ענף, כדי שכל פתיחה תעבור יומן.
3. **בדיקת שלמות תקופתית** (חישוב SHA-256 מחדש מול הרשום) ומשימה שמזהה אובייקטים יתומים או מסמכים בלי אובייקט.
4. **פורמטים נוספים** (`.doc`, תמונות, Excel, `.eml`, `.msg`) רק עם החלטה איך מסווים בהם PII.
5. **תיקייה מקושרת בדפדפן (כיוון א):** חיבור חד פעמי לתיקיית LALUM, זיהוי תיקיות וקבצים חדשים, הצעת ייבוא בלבד ואישור אנושי. קריאה בלבד, ובלי כתיבה חזרה.
6. **סנכרון שרת (כיוון ב):** לפי `docs/matter-folder-sync-design.md`, אחרי הפעלת הדואר.
